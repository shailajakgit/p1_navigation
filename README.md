# Banana Collector — Navigation Project

A Python 3 / PyTorch reinforcement-learning agent for Udacity's Banana Collector environment. The agent combines Double DQN, a dueling Q-network, prioritized experience replay, and three-step returns.

## Project details

The agent navigates a square arena, collecting yellow bananas and avoiding blue bananas.

| Property | Value |
| --- | --- |
| State space | 37 continuous numerical observations describing velocity and ray-based perception |
| Action space | Four discrete actions: forward, backward, turn left, turn right |
| Yellow banana reward | +1 |
| Blue banana reward | -1 |
| Episode duration | 300 steps in the supplied build used here |
| Success criterion | Average undiscounted episode score of at least +13 over 100 consecutive episodes |

The project uses numerical observations, not the optional pixel-based task. Episode score is the sum of rewards; it is not the discounted training target.

With learning rate `1e-4`, the saved log records a rolling 100-training-episode mean of 13.56 at episode 1000. Thus the logged training window meets the rubric's numerical success criterion by episode 900; the exact first crossing requires the full per-episode scores. See [Report.md](Report.md) for the learning algorithm, hyperparameters, results, and future work.

## Getting started

### Environment executable

Download the appropriate Banana executable from the [Udacity Navigation project instructions](https://github.com/udacity/deep-reinforcement-learning/tree/master/p1_navigation). Extract the build and update the notebook's `UnityEnvironment(file_name=...)` paths.

For the macOS layout above, place `Banana.app` beside the notebook. Linux and Windows users must use the corresponding executable path instead.

This project uses the legacy `unityagents` 0.4.0 API. Modern `mlagents` is not a drop-in replacement. The prebuilt executable does not require installing the Unity Editor.

### Tested local setup

The local connection was tested with native ARM Python 3.10.13 on an Apple Silicon Mac, using the Intel Banana application through Rosetta. Python imports, reset, random actions, and coexistence with PyTorch passed smoke tests. Other platforms may need different packages or executable permissions.

Do not install the original course requirements unchanged: their TensorFlow, PyTorch, gRPC, and Protobuf pins belong to a much older stack.

### Install dependencies

Create a separate environment:

```bash
python3.10 -m venv ~/banana_env
source ~/banana_env/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install "numpy==1.26.4" "protobuf==3.20.3" grpcio Pillow
```

On Windows, activate the environment using its `Scripts` activation command instead.

Install the course's legacy communication package without its historical dependency pins:

```bash
git clone https://github.com/udacity/deep-reinforcement-learning.git
cd deep-reinforcement-learning/python
python -m pip install --no-deps .
python -m pip install torch
```

Protect the core installed versions while adding notebook tools:

```bash
python -c "from importlib.metadata import version; print('\n'.join(f'{p}=={version(p)}' for p in ['numpy','protobuf','grpcio','torch','Pillow']))" > banana-core-constraints.txt
python -m pip install -c banana-core-constraints.txt matplotlib ipykernel notebook
python -m ipykernel install --user --name banana_env --display-name "Python (banana_env)"
```

`notebook` is optional if an existing Jupyter installation or editor provides the interface. Choose the registered banana_env kernel in that interface.

This is a customized legacy installation. Pip may report that unityagents' declared dependencies are unsatisfied because its metadata still lists the old pins. Do not downgrade the tested runtime solely to silence those declarations. Verify functionality instead:

```bash
python -c "import torch, matplotlib; from unityagents import UnityEnvironment; print(torch.__version__); print('MPS:', torch.backends.mps.is_available()); print('Imports OK')"
```

Run the notebook's random-action test before training. On macOS, install Rosetta if prompted for the Intel application. Approve a trusted course executable through the application-specific macOS security workflow if necessary; do not disable system security globally.

Preserve the successful configuration:

```bash
python -m pip freeze > banana-working-requirements.txt
```

For reproduction, use the recorded package versions together with this legacy-package installation procedure. An unpinned installation is not guaranteed to reproduce the same package selection.

## Instructions

### Train the agent

1. Activate banana_env and change to the directory containing the project notebook and Python files.
2. Start `jupyter notebook`, or open the notebook in an existing interface.
3. Select the **Python (banana_env)** kernel.
4. Open `p1_navigation_my_agent_slow_lr_submission.ipynb`.
5. Replace all machine-specific Banana paths with the location of your executable.
6. Execute cells in order, including the environment inspection and random-action test.
7. Run the training cell that calls `scores = dqn_w_diag()`.

The notebook imports `Agent` from `dqn_agent_slow_lr`. Defaults are 2400 training episodes, subject to the implemented diagnostic-based stopping condition. Each episode runs until Unity reports `local_done[0]`; the function's `max_t` argument is currently unused by the training loop.

The notebook displays a per-episode reward plot from `scores`. The report describes how to include this plot in the submitted report.

### Run the trained agent

Ensure `checkpoint.pth` is present. After closing any existing Banana instance, execute the notebook's **Watch a Smart Agent!** section. It creates a 37-input, four-action agent, loads the online-network weights, and runs five greedy demonstration episodes.

Update `./Banana.app` for your platform. When loading weights on another device, add an appropriate `map_location` to `torch.load` if necessary. Load only trusted model files.

The model uses MPS when available and otherwise CPU. CUDA device selection is not implemented. The saved checkpoint contains policy weights, not the full optimizer/replay/target-network state required for exact training continuation.

Close the environment when finished. Do not launch another instance on the same default communication worker while one remains open.
